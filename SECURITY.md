# 安全政策 / Security policy

## 中文版

目前支援最新標記的預覽版。請透過 GitHub private vulnerability reporting 回報漏洞；在公開倉庫建立前，可將加密報告交給維護者指定的私人管道。請提供受影響版本、最小重現、影響與建議修復，且不要附真實使用者資料或有效憑證。維護者會在 5 個工作日內確認收到，並依嚴重度協調修復與揭露。

若發現疑似憑證，請立即撤銷或輪替；刪除 Git 歷史中的字串不能取代撤銷。不要對他人系統進行破壞性測試、資料外洩或服務阻斷。

## English version

The latest tagged preview is supported. Use GitHub private vulnerability reporting once the public repository exists; before then, send an encrypted report through the private channel designated by the maintainers. Include the affected version, a minimal reproduction, impact, and a proposed fix without real user data or active credentials. Maintainers aim to acknowledge reports within five business days and coordinate remediation and disclosure based on severity.

Revoke or rotate any suspected credential immediately. Removing a string from Git history does not replace revocation. Do not perform destructive testing, expose data, or disrupt systems you do not own.
